## Status meanings

- **VERIFIED**: the referenced artifact, configuration or recorded outcome was inspected; this does not mean independently audited.
- **TESTED LOCALLY**: the named command/behavior was actually exercised in this audit environment.
- **LOGICALLY COVERED**: supported by source inspection, not exhaustive dynamic proof.
- **UNVERIFIED**: no adequate current evidence was available.
- **KNOWN LIMITATION**: an intentional boundary or observed unresolved behavior.
- **SUPERSEDED**: an earlier observation kept for provenance because a later row replaces its status; the old run is not re-executed or re-claimed.
- **NOT APPLICABLE**: the requirement does not apply to this offline product.

Historical rows retain their own dates and tested revisions. A passing old result alone does not verify later source, dependencies or environments. At baseline, `git diff v0.1.1 -- src tests integration checks/resources` was empty; this is source equivalence, not a new execution of every historical test environment.
